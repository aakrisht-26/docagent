# NOT INSTALLED ON LINUX, which is what the hosted deployment runs. Full
# reasoning in DEPLOYMENT.md; the short version:
#
# StructureRecognitionSkill gates on a CUDA GPU before it imports anything
# paddle-shaped. `_cuda_driver_present()` returns False on a GPU-less host, so
# `_detect_gpu()` short-circuits WITHOUT importing paddle, and `execute()`
# returns the document untouched before `_get_engine()` (the only paddleocr
# import site, line ~192) is ever reached. Community Cloud has no GPU, so on
# the deployment this is 30 packages and ~285 MB of wheels (measured by
# resolving the hosted set both ways) that are downloaded, unpacked, and never
# imported — into a ~1 GB container where out-of-memory kills are already a
# documented failure mode.
#
# It also removes a SECOND OpenCV. paddleocr -> paddlex[ocr-core] depends on
# opencv-contrib-python==4.10.0.84, which lands beside the pinned
# opencv-python-headless==4.8.1.78. DEPENDENCIES.md section 1 records that
# hazard — a silent OpenCV swap changes OCR output with no import error,
# because minAreaRect's angle convention moved across 4.x and the deskew step
# branches on it — and records it as fixed locally on 2026-07-29. The hosted
# build was reintroducing it.
#
# The marker is `!= "linux"` because that is the only axis pip can express;
# there is no marker for "has a GPU". The cost is that a LINUX developer with a
# GPU no longer gets paddle automatically and must install it by hand. That
# path is not currently supported anyway: GPU_SETUP.md is written for Windows
# and install_gpu_paddle.bat is a Windows batch file.
#
# Do NOT drop these lines entirely. install_gpu_paddle.py refuses to run when
# the CPU wheel is absent ("paddlepaddle is not installed in THIS Python
# environment"), so removing them outright would break the documented GPU
# upgrade path on the machine that actually uses it.
paddlepaddle>=2.6.2 ; sys_platform != "linux"
paddleocr>=2.6.0.3 ; sys_platform != "linux"

# Document-chat retrieval (embeddings)
# Pinned: stored vectors are only comparable to vectors from the same model, and
# DocumentStore records the model name so a mismatch is detected rather than
# silently compared. Pulls in torch transitively — see DEPENDENCIES.md for the
# install footprint and first-run download. Chat degrades to keyword overlap if

sentence-transformers==5.4.0

# torch, CPU-only, on Linux ONLY.
#
# The default PyPI torch wheel for Linux is a CUDA build: 527 MB itself, plus
# nvidia-cudnn/nccl/cusparselt/nvshmem and triton as hard dependencies under a
# `platform_system == "Linux"` marker — about 1.5 GB downloaded and roughly
# 3 GB unpacked, none of it usable on a CPU-only host. Those packages do not
# exist on Windows or macOS, which is why a local install never sees them and
# why this only became visible when targeting a Linux deployment.
#
# The marker below is what keeps local development untouched: on Windows and
# macOS the line is skipped entirely and torch continues to arrive as a plain
# transitive dependency of sentence-transformers, exactly as before. Verified
# with `pip install --dry-run -r requirements.txt` on Windows: no change.
#
# The `+cpu` local version only exists on the PyTorch index, so pip is forced
# to take it from there rather than picking the CUDA wheel off PyPI — an
# --extra-index-url alone would leave the choice ambiguous. That index hosts
# only torch-family packages, so it cannot shadow anything else here.
# The version is pinned to MATCH LOCAL (2.7.1), not to the newest available.
# The 18/18 retrieval eval in tests/e2e/rag_eval/ was measured on 2.7.1, and
# four of its margins sit between 0.028 and 0.047 — narrow enough that a
# numerical shift across releases could flip a case with no visible symptom.
# 2.7.1+cpu publishes Linux wheels for cp39 through cp313, which covers every
# interpreter Community Cloud offers, so parity costs nothing here.
#
# Measured, so the risk is sized rather than assumed: running the same model on
# GPU and on CPU at this version moves a similarity score by at most 1.6e-07,
# against a narrowest real margin of 2.8e-02 — about five orders of magnitude
# of headroom. Device is therefore not the risk; version drift would be, and
# pinning removes it. Re-run tests/e2e/rag_eval/run_eval.py after any change to
# this line; it costs nothing and prints the number.
--extra-index-url https://download.pytorch.org/whl/cpu
torch==2.7.1+cpu ; sys_platform == "linux"

# Audio & YouTube Processing
# ffmpeg itself is a SYSTEM BINARY, not a pip package — see README step 3.
# `pydub` and `ffmpeg-python` were previously declared here. Both were removed:
# neither is imported anywhere in the codebase, neither was installed, and the
# pin `ffmpeg-python>=0.2.1` was unsatisfiable (0.2.0 is the newest release),
# which made `pip install -r requirements.txt` fail outright on a fresh clone.
# DELIBERATELY NOT PINNED — floored instead. Full reasoning in DEPENDENCIES.md
# section 7; the short version:
#
# yt-dlp tracks server-side changes at YouTube that this project does not
# control. Stable releases land every 11 days (median, measured over 36
# releases since Jan 2025), because that is the pace of the thing it is
# chasing. A `==` pin would work until YouTube's next change and then be broken
# for every fresh clone, fixable only by a commit here — whereas an unpinned
# break is fixed by `pip install -U yt-dlp`. A download against 2026.7.4 failed
# for exactly this reason and 2026.8.19 fixed it with no change to this repo.
#
# This is the opposite of the call made for torch and sentence-transformers,
# and the difference is that those sit in the retrieval measurement path where
# version drift moves a scored number SILENTLY. Nothing here imports yt_dlp in
# a test, and its failures are loud: the download raises and the pipeline
# reports it. The API used is six long-stable options on YoutubeDL; the churn
# is all in the extractors, which is the part a pin would freeze broken.
#
# The floor is the version verified end-to-end by tests/e2e/e2e.py::youtube.
# It cannot promise a future release works, but it refuses one already known
# not to — a lower bound on known-good rather than an upper bound freezing
# time. The old floor, >=2024.01.01, admitted 58 releases and expressed nothing.
yt-dlp>=2026.8.19

# The second half of AudioReaderSkill._find_ffmpeg(): if no ffmpeg is on PATH,
# it falls back to the binary bundled in this wheel. That fallback was dead on
# any machine that had not installed this by hand — it was present in the
# development environment but never declared, so a fresh clone got the PATH
# branch or nothing. Declaring it means YouTube works after
# `pip install -r requirements.txt` alone, with no system install and no admin
# rights. Small (~20 MB) and pure-binary, so it costs little to carry.
imageio-ffmpeg>=0.4.9
